Where Ferny is today

10 min

A 420 px right-docked chat panel inside Worksuite PWA. Conversational, screen-aware, can attach files, render HTML artifacts, drive AG Grids, and navigate the app. Brand-marked "Beta." Talks to a separate AI orchestrator over GraphQL (sendChatMessage mutation) — JWT-authenticated, single-tenant on the frontend.

Shipping today

  • Streaming-style chat with server-side sessions + 50-chat local history
  • File attach (CSV / TSV / XLSX up to ~500 KB) inlined into prompt
  • HTML artifact rendering (sandboxed iframe + "Open" button)
  • Grid actions: applyGridFilter, clearGridFilter, setGridSearch
  • Navigation: navigateTo, openPanel, closePanel
  • Auto-injected page context (data key + column schema)

Brand & UX

  • Ferny green #4a7c59 → #69936C gradient logo
  • PT Serif wordmark, Inter body
  • Sparkle ✦ everywhere, soft borderless surfaces
  • Two un-wired "Ask Ferny…" widgets on Home dashboard dead UI

What's brittle today

10 min
  • Hardcoded localhost fallback in prod path. Config.aiOrchestratorUrl || "http://localhost:5291/graphql" — if env unset, requests silently target localhost. Sev 1
  • Pending-action queue is single-slot. Multi-step server responses overwrite each other; only the last action survives. Multi-step automation will be flaky. Sev 1
  • Frontend trusts the orchestrator entirely. No client-side RBAC, 429 handling, rate-limit UI, or mutation confirmation. First bad mutation in prod = support escalation. Sev 2
  • Chat history is plaintext localStorage. Flagged in the capability report; fine for Beta, not for GA.
  • HTML artifacts: no CSP, no provenance check. Sandbox is allow-scripts — model can paint anything into a blob: URL.
  • Bold rendering by string-split. No real markdown, code fences, or link rendering in plain text replies.
  • Home-page Ferny widgets are dead. Two prominent "Ask Ferny…" inputs go nowhere. Wire or remove before any customer demo.

Six bets for next quarter

15 min · pick two
1

Real streaming (SSE or GraphQL subscriptions)

Time-to-first-token is the single biggest perceived-intelligence lever. Current "Thinking…" spinner kills the magic.

Effort: M · Impact: XL
2

Per-module tool registry (MCP-style)

Today the 6 tools are hardcoded in fernyActionSlice.ts. Let Fulfill / Produce / Restock / Forecast each declare their own tools, validators, and confirmations.

Effort: L · Impact: XL
3

Review-then-execute mutation UX

Diff card → confirm → apply → verify SELECT. Turns Ferny from finder into doer without making the first wrong mutation a fireable offense.

Effort: M · Impact: L
4

"Revert what Ferny just did" toast

One-click undo for any grid or navigation action Ferny performs. Trust accelerator; minimal code.

Effort: S · Impact: M
5

Wire the Home dashboard entry points

The two dead "Ask Ferny" widgets on the Home page are the most valuable real estate in the app. Turn them into ambient command bars.

Effort: S · Impact: M
6

One Ferny, two skins (PWA + Produce desktop)

The Produce WinForms app already has its own Ferny panel. Unify on a single orchestrator so customers get the same brain whichever app they're in.

Effort: L · Impact: L

Decisions to leave with

Tied to mutation execution + RBAC.

Decision unblocks bet #6.

Blueprint is currently the source of confusion, not truth.
⌁

The three lines for the slide

1. Ferny ships behind a flag and can already navigate the app and drive grids — but it's a polished demo, not yet a workflow tool.
2. Code has drifted from the blueprint: no SSE, no streaming, no tool registry, no cost telemetry. Pick one to fix this quarter — streaming alone would change every customer's first impression.
3. The frontend trusts the orchestrator completely — no client-side RBAC, rate-limit UI, abort, or mutation confirmation. Before Ferny moves from "reads things" to "changes things," we need a review-then-execute UX pattern.
